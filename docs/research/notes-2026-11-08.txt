Reproduce the existing SecondShelf visual system described below. Do not reinterpret it, replace its typography with a generic SaaS scale, enlarge all dashboard headings, or apply one uniform font size to every component.

Use Plus Jakarta Sans for headings and selected prominent numbers, Inter for interface text, and IBM Plex Mono selectively for identifiers and technical data.

Preserve the specified font weights, including intermediate weights such as 550, 650, and 750. Preserve negative heading letter spacing.

Build desktop and mobile as different arrangements of the same components. Do not scale the entire desktop interface down.

The desktop workspace uses a fixed sidebar, a top header, a constrained content area, four metric columns, asymmetric dashboard grids, and compact data tables. Mobile uses a navigation drawer, two metric columns, stacked panels, and inventory cards instead of a compressed table.

26. Why another implementation may look different
Ask the other AI to check these before redesigning anything:

Wrong font actually rendering
The stylesheet may name Plus Jakarta Sans while the browser is displaying a fallback.

Only loading regular and bold weights
This changes the appearance of 550, 650, and 750.

Missing negative tracking
The headings use tight spacing. Normal letter spacing will look noticeably different.

Oversized dashboard typography
This dashboard does not use 20px panel headings and 16px table text.

Using IBM Plex Mono for all numbers
Large metric values and marketplace prices use Plus Jakarta Sans. Mono is selective.

Using one font everywhere
The distinction between heading, interface, and technical text is intentional.

Incorrect content width
A 238px sidebar and 34px desktop gutters are part of the composition.

Equal-width dashboard panels
The chart and attention panel are asymmetric: 1.7fr versus 1fr.

Excessive card rounding or shadows
Most surfaces use a 6px radius and a subtle border.

Shrinking desktop tables on mobile
Inventory becomes structured cards with separate quantity, expiry, and status areas.

Applying mobile overrides in the wrong order
The media queries accumulate. A 390px screen receives the 1200px, 1000px, 900px, and 480px overrides.
